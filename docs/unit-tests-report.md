# Отчёт по лабораторной работе: тестирование геометрических фигур с помощью unittest

## 1. Цели и задачи тестирования

**Цель тестирования** — проверить корректность работы функций вычисления площади и периметра геометрических фигур с использованием стандартного модуля Python `unittest`.

Для достижения цели были поставлены следующие задачи:

- Проверить правильность вычисления площади круга, прямоугольника, квадрата и треугольника.
- Проверить правильность вычисления периметра круга, прямоугольника, квадрата и треугольника.
- Проверить поведение функций при нулевых значениях параметров.
- Проверить обработку отрицательных значений и некорректных входных данных.
- Выявить возможные недостатки реализации.
- Зафиксировать результаты выполнения тестов и сформулировать выводы.

## 2. Описание тестируемого продукта

Тестируемый продукт представляет собой набор модулей Python для вычисления геометрических характеристик четырёх фигур:

- **Круг (`circle.py`)** — вычисление площади и длины окружности по радиусу.
- **Прямоугольник (`rectangle.py`)** — вычисление площади и периметра по ширине и высоте.
- **Квадрат (`square.py`)** — вычисление площади и периметра по длине стороны.
- **Треугольник (`triangle.py`)** — вычисление площади по основанию и высоте, а также периметра по трём сторонам.

Программа состоит из функций, принимающих числовые параметры и возвращающих результат вычисления.

## 3. Область тестирования

Тестирование охватывает следующие модули и функции:

| Модуль | Функции | Проверяемые характеристики |
|---|---|---|
| `circle.py` | `area(r)`, `perimeter(r)` | Площадь и длина окружности |
| `rectangle.py` | `area(a, b)`, `perimeter(a, b)` | Площадь и периметр прямоугольника |
| `square.py` | `area(a)`, `perimeter(a)` | Площадь и периметр квадрата |
| `triangle.py` | `area(a, h)`, `perimeter(a, b, c)` | Площадь и периметр треугольника |

В ходе тестирования проверяются:

- Корректные положительные значения параметров.
- Нулевые значения параметров.
- Отрицательные значения параметров.
- Некоторые некорректные типы входных данных.
- Обработка сторон, не удовлетворяющих условию существования треугольника.

Тестирование производительности, безопасности и графического интерфейса не проводилось, поскольку данные аспекты не относятся к функциональности рассматриваемых модулей.

## 4. Стратегия тестирования

Для тестирования использовался модуль `unittest`, входящий в стандартную библиотеку Python.

Применялись следующие методы и техники тестированяи:

1. **Функциональное тестирование** — проверка правильности результатов вычислений.
2. **Тестирование граничных значений** — проверка поведения функций при нулевых значениях параметров.
3. **Негативное тестирование** — проверка поведения при отрицательных значениях и некорректных входных данных.
4. **Модульное тестирование** — независимая проверка функций каждого модуля.
5. **Автоматизированное тестирование** — запуск тестов с помощью средств Python.

Для проверки результатов использовались методы `assertEqual`, `assertAlmostEqual` и `assertRaises`.

Метод `assertAlmostEqual` применялся для сравнения результатов вычислений с плавающей точкой, например при расчёте площади круга. Метод `assertRaises` использовался для проверки ожидаемых исключений при некорректных входных данных.

Тесты размещены в отдельных файлах:

- `test_circle.py`
- `test_rectangle.py`
- `test_square.py`
- `test_triangle.py`

Для запуска всех тестов можно использовать команду:

```bash
python -m unittest discover -v
```

## 5. Критерии приёмки

Тестирование считается успешно выполненным в части проверки заявленной функциональности, если соблюдаются следующие условия:

- Функции корректно вычисляют площадь и периметр при допустимых положительных значениях параметров.
- Результаты вычислений совпадают с ожидаемыми значениями.
- При нулевых значениях параметров функции возвращают ожидаемые результаты.
- Результаты выполнения тестов зафиксированы и проанализированы.
- Выявленные ограничения и дефекты описаны в отчёте.

Для негативных сценариев ожидаемое поведение должно определяться требованиями к функциям. Если тест проверяет предполагаемую обработку некорректных данных, но исходный код её не реализует, такой результат фиксируется как обнаруженное ограничение или потенциальный дефект.

Поскольку изменение исходного кода запрещено условиями работы, исправление обнаруженных недостатков в рамках данной лабораторной работы не выполняется.

## 6. Ожидаемые результаты

По итогам тестирования ожидается получить:

- Подтверждение корректности основных математических вычислений.
- Информацию о поведении функций на граничных значениях.
- Выявление недостатков обработки некорректных входных данных.
- Список пройденных и проваленных тестов.
- Выводы о соответствии реализации проверяемым требованиям.

Предполагается, что тесты с корректными положительными значениями и нулевыми параметрами будут пройдены при соответствии ожидаемых результатов реализации.

Некоторые негативные тесты могут завершиться неудачей, если функции не проверяют допустимость входных параметров. Такие результаты необходимы для документирования ограничений программы.

### Анализ проваленных тестов

В ходе тестирования выявлены следующие проблемы:

1. **Круг (`circle.py`).** Не прошли проверки `test_negative_radius_area` и `test_negative_radius_perimeter`, поскольку функции не проверяют отрицательное значение радиуса и не вызывают `ValueError`. Также не прошли `test_complex_radius_area` и `test_complex_radius_perimeter`: текущая реализация допускает комплексные числа в арифметических операциях и не вызывает ожидаемый `TypeError`.

2. **Прямоугольник (`rectangle.py`).** Не прошли проверки `test_negative_side_area` и `test_negative_side_perimeter`, поскольку функции не проверяют отрицательные размеры. Проверки `test_complex_side_area` и `test_complex_side_perimeter` также завершились неудачей: арифметические операции с комплексными числами выполняются без `TypeError`.

3. **Квадрат (`square.py`).** Не прошли проверки `test_negative_side_area` и `test_negative_side_perimeter`, так как функции не отклоняют отрицательную длину стороны. Тесты `test_complex_side_area` и `test_complex_side_perimeter` не прошли, поскольку функции выполняют вычисления с комплексными числами без вызова `TypeError`.

4. **Треугольник (`triangle.py`).** Не прошли проверки `test_negative_base_area`, `test_negative_height_area` и `test_negative_side_perimeter`, так как функции не проверяют отрицательные параметры. Тест `test_invalid_triangle` также завершился неудачей: функция периметра не проверяет неравенство треугольника. Кроме того, проверки `test_complex_base_area` и `test_complex_side_perimeter` не прошли, поскольку текущая реализация допускает комплексные значения.

### Общая оценка

Проверки с обычными положительными, нулевыми и дробными значениями завершились успешно. Это показывает, что основные математические вычисления выполняются корректно для протестированных числовых параметров.

В то же время выявлено отсутствие проверки отрицательных значений и геометрической корректности треугольника. Кроме того, функции принимают комплексные числа, хотя тестами предусмотрено ожидание `TypeError`.

Важно отметить, что провал теста означает несоответствие фактического поведения программы ожидаемому в тесте. Это не обязательно является ошибкой исходного кода, если соответствующие ограничения не были установлены требованиями к библиотеке.

Исходный код модулей фигур не изменялся. Все выявленные несоответствия зафиксированы для дальнейшего анализа.

## 8. Выводы из результатов тестирования

В ходе лабораторной работы были разработаны модульные тесты для проверки функций вычисления площади и периметра круга, прямоугольника, квадрата и треугольника. Для автоматизации проверки использовался стандартный модуль Python `unittest`.

Тестирование позволяет проверить правильность основных вычислений, исследовать поведение функций при нулевых значениях и выявить ограничения при обработке некорректных параметров.

Основное внимание было уделено функциональным, граничным и негативным сценариям. Проверки показали необходимость учитывать не только правильность математических формул, но и требования к входным данным.

Обнаруженные ограничения могут быть связаны с отсутствием проверки отрицательных значений, типов параметров и допустимости сторон треугольника. При этом нарушение требований можно подтвердить только в том случае, если соответствующие ограничения явно предусмотрены спецификацией.
